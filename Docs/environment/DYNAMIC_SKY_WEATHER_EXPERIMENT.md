## Existing rendering architecture: audit before touching
- `Assets/Script/GroundPresentation.cs` creates `skyTiles`, loads biome-specific `TerrainArtwork.Sky` with `Resources.Load<Sprite>`, `SetLayerSprite(skyTiles, use ? next.Sky : legacyFar, Color.white)`, and toggles sky layer. It also renders parallax far backgrounds and has `LayoutSky()` and sky loop movement. **Do not remove mountain/near/far/ground**, nor unintentionally remove the original far parallax fallback.
- Sky is rendered within a 2D layered UI/presentation. HDR skyboxes normally render in camera background, **not automatically inside UI sorting order**. Prove an appropriate integration (e.g. background sky camera with compatible render path, or render-to-texture projected/panoramic sky sampler) in Unity 6 on the actual camera/canvas. The visual must be *behind all mountains, trees, terrain, heroes, monsters and interactive UI* without z-fighting, stretching, camera hitch or gaps on pan/resize. Avoid replacing project pipeline or changing camera tracking/physics.
- Existing `Resources/Environment/*/sky*.png`, `StreamingAssets/ArtSource` remain intact. A reversible feature flag must allow A/B test legacy sky vs HDR sky; do not render both sky layers simultaneously. If HDR sky integration fails, fallback to legacy sky with explicit log, never a blank screen. Sky at different time of day should remain coherent (night vs daylight); check pack actually has suitable textures before assuming it includes day/night.
- Inspect `Assets/Script/EnvironmentManager.cs`, `GroundPresentation.cs`, `WorldMapCatalog.cs`, `SaveManager` and root GameManager timing before implementation. Distinguish visual environment from gameplay environmental Qi-density heatmap or map biome art.

## Clock / climate requirements
- 780 **real-time** elapsed seconds per 24h when game is running. Prefer a deliberately selected timebase (e.g. unscaled realtime to keep clock independent from combat speed); define/document pause/background focus behavior. Do **not** automatically simulate days during offline/closed-app time without separate approval. Persist current day index and time-of-day, plus weather seed/state. Save/load must resume consistently, including old saves migration.
- Day phase transitions smooth: configurable dawn around 05:00–08:00, day 08:00–17:00, dusk 17:00–20:00, night 20:00–05:00. Those phase boundaries are initial tuning only; no abrupt hard switch except initial boot/Load/map travel. Lighting/tint should not tint HUD, UI text, damage numbers or characters unreadably. Avoid shader high-cost per frame.
- Weather states: clear, cloudy, fog, light rain, heavy rain. Define weather weights by biome or region, not arbitrary global equal percentages. **Rain should not occur in unsuitable indoor maps/cave** unless explicitly configured. Avoid unsupported weather types (snow/thunder) in this slice; reserve architecture for later.
- Randomized weather should be **deterministic and persisted** with world seed + world day + map/region + weather slot (or explicit persisted outcome). Stable across Load/Retry, fast travel, window resize. Transitions should blend over seconds rather than rapidly flicker. Weather should not reshuffle every few seconds. Allow manual developer override/debug controls; normal players should not see test controls.
- Rain Maker 2D mode must be camera-follow/viewport aware, correct depth and scaling for orthographic or UI camera, cover full gameplay viewport and move with camera. Inspect shaders/materials and ensure rain isn't black or invisible in Windows Build. Rain visual budget should remain low in background idle conditions, no expensive always-active particles on clear days. Preserve legacy audio controls and do not automatically add loud looping rain audio; check whether rain audio can be disabled/separated.
- No weather effect on combat stats, monster spawn, loot, Qi or story rules in this prototype. The goal is **visual/environment only**; gameplay effect needs future explicit design.

**Do not import all packages together**. Evaluate individually in a disposable Unity test project or isolated worktree, record packages, shader errors, sorting, FPS and visual results. Only a selected minimal adapter belongs in the integrated build.
